Windows Server 2016: Bugcheck 0x9F due to CPU busy trimming the working set of
RStudio process rsession-utf8.exe Important: This was authored via
https://aka.ms/contentidea. Follow Content Idea (CI) 197545 link for any
updates. Author: Khalid Sabri Summary/Symptom Reported on Windows Server 2016
Reported symptoms System crashes with bugcheck DRIVER_POWER_STATE_FAILURE,
hexadecimal value 9F. But the issue can be manifested in other ways such as high
CPU, system hang or slowness or other bugcheck codes Cause The memory dump shows
the system is locked up with many threads from various processes waiting for
long time on various types of locks. Following the wait chains lead to the
thread running on CPU#0, which has been running for long time at high priority
trimming the working set for an instance of the process rsession-utf8.exe. A
process working set is the process memory pages that are resident in the
physical memory. This rsession-utf8.exe process instance has massive memory
usage of 30GB+ of physical memory when it had run for a total time of only
~3hrs. Furthermore, there are multiple instances of the rsession-utf8.exe with
high memory usage, one of them alone using ~110GB of memory. rsession-utf8.exe
is launched by rstudio.exe, which is part of RStudio Desktop, an integrated
development environment (IDE) with a set of tools built to help develop apps
using the R and Python languages. RStudio is owned by Posit Software. The system
lockup caused one of the power requests (to power on COM2 serial port) to block
hence triggering the power manager kernel component watchdog timeout mechanism
(10min) to crash the system with bugcheck DRIVER_POWER_STATE_FAILURE (9F). This
is just a symptom of the system lockup for long period of time. Article
resolution Follow up with the vendor for RStudio to investigate the high memory
