ADDS: PKI: Certificate Revocation Fails for LDAP locations for Standalone or
Clustered CAs After Renewing CA with New Key Important: This was authored via
https://aka.ms/contentidea. Follow Content Idea (CI) 195706 link for any
updates. Author: Chris Cartwright (CSS DS) Summary/Symptom Abstract Customers
may experience revocation failures on Standalone or Clustered CAs after renewing
with a new private key. This should only apply to LDAP locations. HTTP locations
are either updated manually or automatically and should not run into this
problem. Symptoms PKIView displays the error "Unable to download" Revocation
failures in environment for new certificates post CA renewal. Running certutil
-verify -urlfetch against a cert (If publish was done incorrectly) fails with
"Wrong Issuer" Cause When a CA is enrolled with a new private key, the index
value increases. Enterprise, non-clustered CAs take care of this automatically.
Standalone (Non domain joined) and Clustered CAs do not. Standalone CAs that
aren't domain joined won't be able to update LDAP locations. Clustered CAs won't
be able to update LDAP locations because the renewal isn't done from the cluster
resource. It is done from an individual node. This means that certutil
-dspublish must be used. However, documentation on how to leverage certutil is
suboptimal, to say the least. There is a barely noted option for DSCDPCN, that
mentions "DSCDPCN is the DS CDP object CN based on the sanitized CA short name
and key index." This is not even covered on pkisolutions.com or sysadmins.lv,
where we usually go to get better quality documentation. Article resolution
Modify the certutil command to include the index. This index will be found in
C:\Windows\System32\CertSrv\CertEnroll. It will be the number in parenthesis at
the end of the filename. Format: certutil [options] -dspublish CRLfile
[DSCDPContainer [DSCDPCN]] Example for Offline Root Contoso-Root-CA running on
computer ContOffRoot: certutil -f -dspublish
C:\Windows\System32\CertSrv\CertEnroll\Contoso-Root-CA(2).crl RootCA
ContOffRoot(2) Example for clustered enterprise clustered subordinate CA Adatum-
Issuing-CA running on cluster resource AdaSubCA: certutil -f -dspublish
C:\Windows\System32\CertSrv\CertEnroll\Adatum-Issuing-CA(1).crl SubCA
AdaSubCA(1) More information Author chcart@microsoft.com Notes: Support Topics:
