ADDS: Tools: Klist.exe fails to display ticket cache; “Credentials cache
C:\Users\xxx\krb5cc_xxx not found” Important: This was authored via
https://aka.ms/contentidea. Follow Content Idea (CI) 199899 link for any
updates. Author: Gaurav Chavan Summary/Symptom You run “klist.exe” or “klist.exe
tickets” in the user context, and expect to see the user’s Kerberos tickets,
however, you get this error: “Credentials cache C:\Users\xxx\krb5cc_2280025 not
found” You have validated that there are no Kerberos issues, and the client does
appear to acquire and consume Kerberos tickets successfully. Additionally, other
klist switches (like klist get SPN) also fail, with this message: Cause Note
that these errors / messages are not from the Microsoft klist.exe (located under
C:\Windows\System32\), but from a 3rd party version included in the Java
Development Kit (JDK). The customer had installed Eclipse Adoptium JDK, which
inserts its own path in the System variables: Since its path was placed higher
than %SystemRoot%\System32, when they ran “klist.exe”, the JDK version was being
launched instead of the built-in, Microsoft version. This can also be identified
from a Procmon trace, filtered for “Process Create” activity: 8:11:14.1090991 AM
cmd.exe 4524 Process Create C:\Program Files\Eclipse
Adoptium\jdk-23.0.2.7-hotspot\bin\klist.exe SUCCESS PID: 6548, Command line:
klist Article resolution Move the JDK path in the System variables below the
default, Windows paths, so that when you call “klist.exe” from the command line,
it launches the built-in, Microsoft version from the System32 folder. Notes:
Support Topics: Windows\Windows 11\Windows 11 Enterprise and Education, version
24H2\Windows Security Technologies\Kerberos authentication First published: Mar
31, 2025 Keywords: Credentials cache C:\Users\xxx\krb5cc_xxx not found, klist,
JDK
