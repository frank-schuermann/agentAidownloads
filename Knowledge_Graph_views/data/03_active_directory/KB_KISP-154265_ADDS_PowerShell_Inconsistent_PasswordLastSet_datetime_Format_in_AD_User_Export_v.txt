ADDS: PowerShell: Inconsistent PasswordLastSet date/time Format in AD User
Export via PowerShell Important: This was authored via
https://aka.ms/contentidea. Follow Content Idea (CI) 202577 link for any
updates. Author: Mukesh Agarwal Summary/Symptom When exporting Active Directory
(AD) user data using PowerShell, the PasswordLastSet attribute appears in
inconsistent formats across different user entries in the CSV output. This
inconsistency can hinder readability and affect downstream reporting or auditing
processes. Cause PowerShell’s default behavior when exporting DateTime
properties like PasswordLastSet can lead to inconsistent formatting. This
variation is influenced by system locale, regional settings, and how the
DateTime object is serialized during export. Article resolution To ensure
consistent formatting, use a refined PowerShell script that explicitly formats
the PasswordLastSet field before exporting. The recommended format is yyyy-MM-dd
HH:mm:ss. More information Example of a script which can export PasswordLastSet
value for users in consistent format- Import-Module ActiveDirectory $ExportPath
= "C:\AD_Users_PasswordLastSet_Formatted.csv" Get-ADUser -Filter * -Properties
SamAccountName, PasswordLastSet | Select-Object Name, SamAccountName,
@{Name="PasswordLastSet";Expression={$_.PasswordLastSet.ToString("yyyy-MM-dd
HH:mm:ss")}} | Export-Csv -Path $ExportPath -NoTypeInformation -Encoding UTF8
Write-Host "Export complete. File saved to $ExportPath" Notes: First published:
May 15, 2025 Keywords: ADUserExport, PowerShell, PasswordLastSet, Audit,
DateFormat
