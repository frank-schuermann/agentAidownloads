ADDS: SBSL: Slow logon delays due to drive map GPP settings on Windows Server
2022 running Citrix application Important: This was authored via
https://aka.ms/contentidea. Follow Content Idea (CI) 201250 link for any
updates. Author: Pruthviraju Dobaspet Summary/Symptom Our customer had Windows
Server 2016 Terminal servers in their environment, and they are being now
replaced by Windows Server 2022 Terminal servers (Citrix Servers). Our customer
has observed a login delay in getting one of the GPO processing for mapping the
Network Drives. The shares are hosted on NetApp Appliances and available via DFS
Name spaces. Drive mapping works fine if the customer has rights to the share
and network connectivity from the Remote Desktop host (Running Citrix
Application) to the File share. However, the customer has noticed a considerable
delay of 179328 milliseconds (2.9 minutes) to get on to the desktop. Cause After
a long investigation with multiple sets of SBSL data, there were attempts made
to use NetBIOS protocol on Port 443 and QUIC protocol on port 139. Initially, it
was suggested to disable these protocols on Windows Server 2022, but this did
not help. Further checking the new set of data, it was found that WebDAV
communication is initiated on Windows Server 2022 RDS Server, which was not seen
on Windows Server 2016 RDS Server. It was suggested to disable WebDAV components
by disabling the “WebClient service” on the Windows Server 2022. Article
resolution The delay-causing component was identified on this service request.
Removing the WebDAV component on the RDS if not needed fixed the GPO processing
delays on the server. The customer has seen a significant difference in the
login time after disabling the “WebClient” Service on the server More
information GPO operation log shows we take 160sec to apply GP Drive Maps CSE.
