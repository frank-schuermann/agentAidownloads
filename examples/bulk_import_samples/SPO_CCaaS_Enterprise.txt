## Standard Operations

### Monitoring & Alerting

**Dashboard:** https://grafana.company.com/ccaas-platform

**Key Metrics:**
- Service availability: >99.9%
- API latency p95: <200ms
- Call failure rate: <1%
- Chat response time: <30s

**Alerts:**
- PagerDuty for P0/P1 incidents
- Slack #platform-alerts for P2/P3
- Email for informational notices

### Deployment Procedures

**Standard Release Schedule:**
- Weekly releases: Every Wednesday 10 PM UTC
- Hotfixes: As needed with approval

**Deployment Process:**
1. Code review + approval (2 reviewers)
2. Staging deployment + smoke tests
3. Production deployment (blue-green)
4. 30-minute monitoring period
5. Rollback if error rate >0.5%

**Approval Matrix:**
- Standard release: Team lead approval
- Hotfix: VP Engineering approval
- Emergency fix during outage: On-call engineer (escalate immediately)

### Backup & Recovery

**Backup Schedule:**
- Cosmos DB: Continuous (point-in-time recovery 30 days)
- Configuration: Daily at 2 AM UTC
- Metrics: 90-day retention

**Recovery Time Objectives (RTO):**
- P0 outage: 1 hour RTO
- P1 degradation: 4 hours RTO
- Data loss: 5 minutes RPO

### Security Practices

**Access Control:**
- Production access: MFA + JIT required
- Audit logs: 1-year retention
- Secrets rotation: 90 days

**Compliance:**
- SOC 2 Type II certified
- GDPR compliant
- PCI DSS for payment data

## Common Operations

### Service Restart
- Follow Runbook RB-Service-Restart
- Get approval if peak hours (9 AM - 5 PM local time)
- Requires team lead approval for production

### Configuration Changes
- All changes via GitOps (config repo)
- Review + approval required
- Auto-deployment to staging
- Manual promotion to production

### Incident Response
- P0/P1: Follow SOP-P1-Escalation
- P2: Follow SOP-P2-Incident
- P3/P4: Create ticket, work during business hours

### Known Issues Management
- Document in KG (see Known Issues Guide)
- Link to affected services
- Update workarounds in FAQ
- Track in Jira (PLAT-XXXX tickets)
